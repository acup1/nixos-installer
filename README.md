# nixos-installer

Терминальный установщик NixOS и редактор конфигурации модулей для Linux и macOS. Интерфейс на Rust использует [terminalib](https://github.com/acup1/terminalib).

## Запуск

Команда для Linux и macOS на x86-64 и ARM64

```sh
curl -fsSL --proto '=https' --tlsv1.2 https://github.com/acup1/nixos-installer/releases/latest/download/bootstrap.sh | sh
```

Скрипт определяет ОС и архитектуру, скачивает бинарник и проверяет его SHA-256 по файлу из того же релиза. Если Nix отсутствует, скрипт устанавливает его официальным установщиком. [Установка Nix](https://nixos.org/download/) · [Файлы релиза](https://github.com/acup1/nixos-installer/releases/latest)

Если бинарник уже установлен, выполните `nixos-installer`. При доступном `config.nix`, flake хоста и списке модулей откроется редактор. На Linux без селектора откроется мастер установки. При ошибке в существующей конфигурации установщик покажет её причину.

Управлять можно клавиатурой и мышью. Tab и стрелки перемещают фокус, Space выбирает модуль, Enter открывает редактор, Ctrl+N и Ctrl+P переключают шаги.

## Настройка системы

1. Редактор использует `NIXOS_BASE_CONFIG`, `~/.config/config.nix`, ранее сохранённый селектор или `/etc/nixos/config.nix` в порядке приоритета. Поле `flakeDir` задаёт путь к flake хоста. На странице источников можно сменить селектор, задать другой flake или явно выбрать конфигурацию через `путь#имя`. Добавьте доверенные Git-репозитории с модулями и выберите для них ветку, тег или коммит.
2. Локальный режим читает рабочую копию или скачивает репозиторий. Закреплённый режим записывает в конфигурацию удалённый URL и точную ревизию Git. При локальной установке в новую систему мастер копирует выбранную ревизию на целевой диск.
3. На странице **Modules** выберите компонент. Его пакеты и булевы параметры переключаются пробелом, Enter или щелчком. Когда вы снимаете отметку с пакета, модуль отключает и связанные с ним сервисы. Ctrl+R возвращает настройку по умолчанию. Если сохранён старый список замены пакетов, нажмите **Restore module packages**, чтобы вернуться к выбору отдельных пакетов.
4. Проверьте выбор. Команда **Save** сохраняет селектор. При первом изменении установщик сохраняет исходный файл рядом. Одно нажатие **Rebuild** сохраняет выбор и запускает `nh os switch` или `nh darwin switch` с именем конфигурации из выходов flake. Если хост применяет Home Manager отдельно от системы, домашняя конфигурация активируется отдельно.

Для перестройки нужны Git, Nix с включёнными flakes, `nh` и доступ к записи в выбранный селектор. Описание интерфейса репозиториев доступно в [JSON Schema](schema/module.schema.json). Пакеты и настройки выбранного репозитория будут исполняться Nix с полномочиями, необходимыми для сборки и активации системы.

## Установка NixOS

### Переход с работающего Linux на том же разделе

1. Сохраните резервную копию важных данных. На машине с удалённым доступом проверьте также доступ к консоли. Сеть новой системы настраивается отдельно, особенно если хост использует статический адрес или Wi-Fi.
2. Выполните команду из раздела «Запуск» и подтвердите запрос `sudo`. На шаге **Installation storage** выберите **Convert this Linux installation to NixOS**. Мастер проверит текущий корневой раздел и загрузчик.
3. На шаге **Review changes** нажмите **Generate installation plan**. Проверьте имя пользователя, корневой раздел и запись загрузки. Нажмите **Apply installation plan** и введите `INSTALL IN PLACE /`.
4. Дождитесь завершения сборки и установки загрузочной записи. Перезагрузите машину, когда будете готовы, и выберите NixOS. При первом запуске миграция сохраняет прежнее дерево системы в `/old-root`. Домашние каталоги остаются в `/home`.

Для перехода нужен доступный на запись локальный раздел ext4, XFS или Btrfs и поддерживаемая схема загрузки. Для UEFI нужен смонтированный EFI-раздел и отключённый Secure Boot. Для BIOS нужен установленный GRUB с поддержкой `custom.cfg`. Контейнеры, корень на LUKS/LVM и сложные схемы монтирования требуют отдельного способа установки. При проверке мастер покажет конкретное препятствие.

### Установка на отдельный диск или раздел

Выберите локаль, часовой пояс, раскладку, сеть, имя компьютера, пользователя и рабочий стол. Мастер поддерживает очистку выбранного диска, установку в выбранный раздел с сохранением соседних разделов и установку в заранее смонтированное дерево. Режим **Install alongside** на диске GPT с UEFI находит свободный диапазон и показывает, какие разделы в нём появятся. Можно выбрать существующий EFI-раздел или создать новый. Для других схем доступна ручная разметка через `cfdisk`.

Поддерживаются UEFI с systemd-boot, BIOS с GRUB, ext4, Btrfs, XFS, LUKS и файл подкачки. Перед записью мастер показывает устройства и список операций, запрашивает подтверждение и повторно проверяет целевые устройства. Пароли вводятся в терминале при запросе `cryptsetup` или `passwd`. Установщик создаёт конфигурацию оборудования и flake в `/etc/nixos`, затем вызывает `nixos-install`.

Для ручной разметки требуется `cfdisk`. При запуске на обычном Linux мастер получает инструменты установки и работы с файловыми системами через Nix. Если live-образ содержит графический Calamares, мастер также позволяет запустить его со штатными модулями этого образа. Выбор, сделанный в TUI, применяется к нативной установке NixOS.

## Разработка и выпуск

```sh
cargo test --locked
cargo run --locked
```

CI проверяет и собирает релизные бинарники для x86-64 и ARM64 под Linux и macOS. Linux-бинарники собираются с musl. Тег вида `v0.1.0` должен совпадать с версией в `Cargo.toml`. После успешных сборок CI публикует четыре файла и `SHA256SUMS` в GitHub Release.
