# nixos-installer

Терминальный установщик NixOS и редактор конфигурации модулей для Linux и macOS. Интерфейс на Rust использует [terminalib](https://github.com/acup1/terminalib).

## Запуск

Команда для Linux и macOS на x86-64 и ARM64

```sh
curl -fsSL --proto '=https' --tlsv1.2 https://github.com/acup1/nixos-installer/releases/latest/download/bootstrap.sh | sh
```

Скрипт определяет ОС и архитектуру, скачивает бинарник и проверяет его SHA-256 по файлу из того же релиза. Если Nix отсутствует, скрипт устанавливает его официальным установщиком. [Установка Nix](https://nixos.org/download/) · [Файлы релиза](https://github.com/acup1/nixos-installer/releases/latest)

Если бинарник уже установлен, выполните `nixos-installer`. При доступном `config.nix`, flake хоста и списке модулей откроется редактор. На Linux без селектора откроется мастер установки. Редактор открывается сразу и загружает каталог в фоне. Esc закрывает редактор и прерывает загрузку. При ошибке в существующей конфигурации установщик покажет её причину.

Управлять можно клавиатурой и мышью. Tab и стрелки перемещают фокус, Space выбирает модуль, Enter открывает редактор, Ctrl+N и Ctrl+P переключают шаги.

## Настройка системы

1. Редактор использует `NIXOS_BASE_CONFIG`, `~/.config/config.nix`, ранее сохранённый селектор или `/etc/nixos/config.nix` в порядке приоритета. Поле `flakeDir` задаёт путь к flake хоста. На странице источников можно сменить селектор, задать другой flake или явно выбрать конфигурацию через `путь#имя`. Добавьте доверенные каталоги компонентов. Для Git-репозитория можно выбрать ветку, тег или коммит.
2. Локальный каталог с файлами `module.json` можно использовать без Git и сети. Добавьте его в **Sources** с пустой ссылкой или `HEAD`, либо укажите абсолютные пути в селекторе: `moduleSources = [ /path/to/catalog "/path/with spaces" ];`. Редактор также находит локальные каталоги уже подключённых компонентов. Каталог показывает все модули и помечает те, которые недоступны в текущей системе. При открытии редактора удалённые источники читаются из кеша, а **Refresh catalog** загружает недостающие копии и обновляет ссылки на ветки. Закреплённый режим сохраняет URL и точную ревизию. Для копирования локального каталога в новую систему требуется чистая Git-копия с коммитом.
3. На странице **Modules** выберите компонент. Его пакеты и булевы параметры переключаются пробелом, Enter или щелчком. Когда вы снимаете отметку с пакета, модуль отключает и связанные с ним сервисы. Строковые параметры с заданными вариантами, например тема, открывают список. Ctrl+R возвращает параметр к значению по умолчанию. В списке темы для этого также есть пункт **Use module default**. Если сохранён старый список замены пакетов, нажмите **Restore module packages**, чтобы вернуться к выбору отдельных пакетов.
4. Проверьте выбор. Команда **Save** сохраняет селектор. При первом изменении установщик сохраняет исходный файл рядом. Одно нажатие **Rebuild** сохраняет выбор и запускает `nh os switch` или `nh darwin switch` с именем конфигурации из выходов flake. Если хост применяет Home Manager отдельно от системы, домашняя конфигурация активируется отдельно.

После загрузки каталога установщик в фоне проверяет upstream текущих веток локальных Git-репозиториев. Если доступны обновления, **Ctrl+U** переводит к строке **Update repository** на странице **Module sources**. Нажатие обновляет чистый checkout только fast-forward и перечитывает каталог. Локальные изменения и разошедшиеся ветки блокируют обновление. Кнопка **Load catalog** повторяет проверку.

На странице **Review changes** галочка **Run garbage collection after rebuild** запускает `nix-collect-garbage` после успешной пересборки. Предыдущие поколения сохраняются для отката. Галочка изначально выключена. **Save** и **Rebuild** запоминают её для текущего селектора. Из установщика можно выйти клавишами **Ctrl+C**.

Управляемый `config.nix` можно форматировать. Установщик принимает изменения отступов и переносов строк между элементами Nix и сохраняет оформление, если выбор остался прежним. Ручные изменения значений и комментариев защищены от перезаписи.

В режиме настройки **System settings** показывает `username` и `hostName` из селектора. Если поле отсутствует, редактор предлагает имя текущего пользователя или хоста. Сохранить предложенное значение можно клавишей Enter в редакторе поля. **Ctrl+R** или пустое поле возвращают наследование из исходного селектора. **Review changes** показывает ожидающие сохранения изменения.

Имена используются конфигурацией Nix. Для систем, созданных мастером, выбранный пользователь объявляется обычной учётной записью. Пароли, группы и существующий домашний каталог сохраняются. При перестройке установщик проверяет имя цели по выходам flake с новыми именами. Если явная цель `#имя` больше не существует, выберите актуальную или уберите фрагмент. Открывайте селектор с сохранёнными переопределениями в версии установщика, которая поддерживает **System settings**.

Для перестройки нужны Git, Nix с включёнными flakes, `nh` и доступ к записи в выбранный селектор. Описание интерфейса репозиториев доступно в [JSON Schema](schema/module.schema.json). В **Modules** и **Review** пометка **Unavailable** означает, что модуль или параметр недоступен в текущей целевой системе. Выбранные значения сохраняются. Селектор подключает выбранные компоненты, а переопределения генерирует для доступных параметров. Платформенные условия компонента определяют, какие его слои и пакеты применяются.

В метаданных `systems` можно указать допустимые системы Nix для модуля или отдельного параметра, например `["aarch64-darwin", "x86_64-linux"]`. Такие ограничения действуют вместе с заявленными платформами слоя и параметра. Поле `choices` задаёт список допустимых значений для параметра `type: "string"`. Если указан `default`, он должен входить в список. Поле `defaultsByPlatform` переопределяет `default` для выбранной платформы. Например, `"default": true, "defaultsByPlatform": {"darwin": false}` включает пакет по умолчанию на Linux и выключает его на macOS. Допустимые ключи — `linux` и `darwin`. Значения должны соответствовать типу параметра и списку `choices`, если он задан. Пакеты и настройки выбранного репозитория будут исполняться Nix с полномочиями, необходимыми для сборки и активации системы.

## Установка NixOS

### Переход с работающего Linux на том же разделе

1. Сохраните резервную копию важных данных. На машине с удалённым доступом проверьте также доступ к консоли. Сеть новой системы настраивается отдельно, особенно если хост использует статический адрес или Wi-Fi.
2. Выполните команду из раздела «Запуск» и подтвердите запрос `sudo`. На шаге **Installation storage** выберите **Convert this Linux installation to NixOS**. Мастер проверит текущий корневой раздел и загрузчик.
3. На шаге **Review changes** нажмите **Generate installation plan**. Проверьте имя пользователя, корневой раздел и запись загрузки. Нажмите **Apply installation plan** и введите `INSTALL IN PLACE /`.
4. Дождитесь завершения сборки и установки загрузочной записи. Перезагрузите машину, когда будете готовы, и выберите NixOS. При первом запуске миграция сохраняет прежнее дерево системы в `/old-root`. Домашние каталоги остаются в `/home`.

Для перехода нужен доступный на запись локальный раздел ext4, XFS или Btrfs и поддерживаемая схема загрузки. Для UEFI нужен смонтированный EFI-раздел и отключённый Secure Boot. Для BIOS нужен установленный GRUB с поддержкой `custom.cfg`. Контейнеры, корень на LUKS/LVM и сложные схемы монтирования требуют отдельного способа установки. При проверке мастер покажет конкретное препятствие.

### Установка на отдельный диск или раздел

На шаге **Installation storage** выберите режим разметки:

- **Create a new layout (erase disk)**. Выберите диск и файловую систему для `/`. Мастер подготовит загрузочный раздел для BIOS или UEFI. Кнопка **Add partition** добавляет раздел для `/home` или данных под `/mnt`. Тип раздела и файловая система выбираются в раскрывающихся списках. Корень занимает оставшееся место.
- **Use existing partitions**. Выберите корень, а при UEFI также EFI-раздел. Галочки форматирования задают, какие файловые системы будут созданы заново. Можно выбрать существующий swap-раздел.
- **Install in unallocated space**. На диске GPT с UEFI мастер находит свободный диапазон и предлагает использовать существующий EFI-раздел или создать новый.
- **Use a mounted target**. Смонтируйте корневую файловую систему под `/mnt` перед созданием плана.

**Enable swap** добавляет подкачку. **Enable hibernation** настраивает возобновление с выделенного swap-раздела без шифрования корня. При создании нового раздела мастер поднимает размер подкачки до объёма RAM с округлением вверх до целого ГиБ. В остальных режимах доступен swap-файл.

Поддерживаются UEFI с systemd-boot, BIOS с GRUB, ext4, Btrfs, XFS и шифрование корня LUKS2. Перед записью мастер показывает устройства и список операций, запрашивает подтверждение и повторно проверяет целевые устройства. Чтобы подтвердить очистку диска или форматирование указанных разделов, введите `yes`. Пароли вводятся в терминале при запросе `cryptsetup` или `passwd`. Установщик создаёт конфигурацию оборудования и flake в `/etc/nixos`, фиксирует входы в `flake.lock` и запускает `nixos-install`.

Кнопка **Manual partition editor (cfdisk)** запускает отдельный редактор для ручной разметки. При запуске на обычном Linux мастер получает инструменты установки и работы с файловыми системами через Nix. Если live-образ содержит графический Calamares, мастер также позволяет запустить его со штатными модулями этого образа. Выбор, сделанный в TUI, применяется к нативной установке NixOS.

## Разработка и выпуск

```sh
cargo test --locked
cargo run --locked
```

CI проверяет и собирает релизные бинарники для x86-64 и ARM64 под Linux и macOS. Linux-бинарники собираются с musl. Тег вида `v0.1.0` должен совпадать с версией в `Cargo.toml`. После успешных сборок CI публикует четыре файла и `SHA256SUMS` в GitHub Release.
